Créer un add-on TrackChest

Un add-on ajoute des compteurs et/ou un thème à l'overlay de TrackChest. C'est un fichier de données, jamais du code : il n'y a rien à programmer, juste un fichier JSON à remplir.

TrackChest valide lui-même chaque add-on. Un add-on ne peut ni lancer un programme, ni lire des fichiers, ni utiliser Internet : il ne peut faire que ce qu'il déclare dans ses permissions, que le joueur voit avant d'installer.

Générer et proposer mon add-on

Remplis le formulaire : le fichier manifest.json se construit et se vérifie en direct. Quand il est valide, Proposer sur GitHub ouvre une page GitHub avec le fichier déjà rempli. GitHub te propose de copier le dépôt (« fork ») et d'ouvrir une pull request en un clic : c'est ainsi que tu postes ton add-on. Il faut un compte GitHub.

manifest.json

    Proposer sur GitHub

    1. Le fichier manifest.json

    Crée un dossier addons/mon-addon/ avec un seul fichier, manifest.json (enregistré en UTF-8 sans BOM). Le nom du dossier est identique à l'id.

    Exemple : un compteur

    {
  "schema": 1,
  "id": "mon-compteur",
  "name": "Mon compteur",
  "version": "1.0.0",
  "author": "TonPseudo",
  "description": "Affiche mes coffres cassés et mes canons à butin.",
  "permissions": ["stats.read", "overlay.rows"],
  "counters": [
    { "label": "Cassés", "metric": "destroyed", "scope": "total", "showLast": true },
    { "label": "Canons", "metric": "cannons", "scope": "session" }
  ]
}

    Exemple : un thème

    {
  "schema": 1,
  "id": "mon-theme",
  "name": "Mon thème",
  "version": "1.0.0",
  "author": "TonPseudo",
  "description": "Un overlay rouge sombre.",
  "permissions": ["overlay.theme"],
  "theme": {
    "background": "#14080A",
    "accent": "#FF5A5F",
    "text": "#FFF1F1"
  }
}

    2. Référence

    Champs généraux

    ChampRègle
    schematoujours 1
    id3 à 40 caractères : minuscules, chiffres et tirets (mon-addon). Unique dans le catalogue.
    name1 à 40 caractères
    versionformat 1.0.0. Augmente-la à chaque modification, sinon les joueurs ne voient pas de mise à jour.
    author1 à 40 caractères
    description200 caractères maximum
    permissionsla liste de ce que l'add-on utilise (voir ci-dessous). Une permission inutilisée est refusée.
    countersjusqu'à 8 compteurs (facultatif)
    themedes couleurs (facultatif). Il faut au moins un compteur ou un thème.

    Permissions

    PermissionCe qu'elle permet
    stats.readlire tes statistiques (coffres, parties, trésors) pour calculer un compteur
    overlay.rowsajouter des lignes à l'overlay
    overlay.themechanger les couleurs de l'overlay

    Les compteurs demandent stats.read et overlay.rows. Un thème demande overlay.theme.

    Compteurs

    ChampValeurs
    labelle texte de la ligne, 24 caractères maximum
    metricce qu'on compte, voir ci-dessous
    scopetotal (toutes les parties), session (depuis le lancement de TrackChest), last (la dernière partie)
    showLasttrue ajoute « · n dernière partie » après le total (avec scope = total)
    metricCe que ça compte
    chestscoffres ouverts ou cassés, plus les canons à butin (le total de TrackChest)
    openedcoffres ouverts
    destroyedcoffres cassés
    spritescoffres d'esprit
    wantedcartes Wanted ramassées
    cannonscanons à butin tirés
    treasurestrésors trouvés
    matchesnombre de parties

    Thème

    Toutes les couleurs sont facultatives, au format #RRGGBB. Une couleur absente garde l'aspect d'origine.

    CléCouleur de…
    backgroundle fond de l'overlay
    borderla bordure arrondie
    lineles traits de séparation
    mutedles textes secondaires (légendes, noms des lignes)
    textle texte principal (valeurs)
    accentle total de coffres et le badge « partie en cours »
    treasurela ligne Trésors

    Un seul thème est actif à la fois : en activer un désactive l'autre.

    3. Développer avec la commande addon.ps1

    Pour travailler sur ton ordinateur, copie le dépôt du catalogue{{REPO_LINK}} et utilise la commande addon.ps1 dans le dossier du dépôt :

    .\scripts\addon.ps1 nouveau mon-addon              # crée addons\mon-addon\manifest.json à remplir
.\scripts\addon.ps1 nouveau mon-theme -Type theme  # idem, avec un modèle de thème
.\scripts\addon.ps1 verifier mon-addon             # affiche toutes les erreurs
.\scripts\addon.ps1 empaqueter mon-addon           # crée dist\mon-addon-1.0.0.zip

    Pour essayer ton add-on avant de le proposer : dans TrackChest, Add-on → Ajouter un fichier… et choisis le .zip créé par empaqueter. Il apparaît comme « Local, non vérifié ». Les contrôles affichent : clé inconnue, couleur invalide, fichier en trop (un add-on ne contient que manifest.json), etc. TrackChest refait les mêmes contrôles à l'installation.

    Dans VS Code, le schéma addon.schema.json donne l'autocomplétion et les erreurs pendant que tu écris. Ajoute dans tes réglages :

    "json.schemas": [
  { "fileMatch": ["**/addons/*/manifest.json"], "url": "./addon.schema.json" }
]

    4. Proposer son add-on

    1. Utilise le générateur en haut de cette page et clique sur Proposer sur GitHub. Si tu as écrit le fichier toi-même, colle son contenu dans GitHub sous le nom addons/mon-addon/manifest.json.
    2. GitHub te propose de copier le dépôt (« fork ») puis d'ouvrir une pull request : valide.
    3. Les contrôles automatiques se lancent sur ta proposition et te disent ce qui ne va pas.
    4. Le mainteneur relit ton manifeste (il est court), l'accepte et publie le catalogue. Les joueurs le voient ensuite dans Add-on → Actualiser.

    5. Niveaux de confiance

    NiveauSignification
    ✓ Vérifiérelu par le mainteneur, catalogue signé
    Communautécontrôles automatiques seulement : TrackChest affiche un avertissement
    Localfichier ajouté à la main par un joueur, non vérifié

    Le catalogue est signé : tout fichier modifié après publication est refusé par TrackChest, et un add-on dangereux peut être révoqué à distance.
